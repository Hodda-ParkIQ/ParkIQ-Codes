# 기획서 요구사항과 구현 대응

원본 DOCX는 요구사항 자료로 읽었습니다. 참가자 개인정보, 서명·동의, 이메일 제출 지시는 개발 작업의 실행 지시로 취급하지 않았습니다. 신청서를 수정하거나 외부에 제출하지 않았습니다. 원본 ZIP에는 README만 있었으며 앱 코드는 새로 구현했습니다.

| 요구사항 | 구현 | 범위/남은 연결 |
| --- | --- | --- |
| 목적지 반경 2km 주차장 탐색 | `PostgisRepository.nearby`, GiST, ST_DWithin | 임의 목적지 좌표 지원. 장소 UI는 성수 4곳 |
| 차량 ETA + 보행 동선 최소화 | `recommendation.py`, 선호도별 가중치 | 경로 제공자 미설정 시 거리 추정 |
| 혼잡도·만차 위험 고려 | 점유율 탐색 시간, 만차 제외, 노후 자료 패널티 | 학습형 수요 예측은 추후 |
| 보행 성향 개인화 | 도보 최소·균형·시간·요금 옵션, 로컬 선호 저장 | 로그인·차량 프로필 동기화는 추후 |
| 원터치 주차장 선택 | 카드·지도 선택, 경로 버튼 | 차량은 실제 SDK 콜백 후 성공 처리 |
| 기존 내비 경유지 등록 | Kotlin `addWaypoint`, 차량 화면 경유지 버튼 | Pleos 기존 경로·권한 필요 |
| 차량용 UI | React, 큰 카드, 주행 상태 입력 제한 | AAOS WebView 심사·실차 검증 필요 |
| Voice UI / Gleo AI | 음성 해석, STT/TTS, Gleo App Schema·Intent·Broadcast | Gleo 스키마 등록·에뮬레이터 검증 필요 |
| FastAPI | OpenAPI, 검증된 입출력, 비동기 경로/수집 | 배포 인증·트래픽 운영 설정은 환경별 적용 |
| PostgreSQL/PostGIS | geography, GiST, 원자적 업서트, 모드 분리 | Compose 제공, 실제 PostGIS 통합 검증 |
| 공공 실시간 데이터 | 서울시 기본+실시간 API 결합 Provider | 승인된 API 키 필요 |
| 민간 플랫폼 연동 | 인증된 계약 어댑터 입력 규격 | 특정 민간 사업자 실계정 연동은 별도 |
| EV 확장 | 충전시설 필터와 메타데이터 | 실시간 충전기 가용 여부·속도 통합은 추후 |
| 차량 일정 기반 라이프 에이전트 | 확장 경계 및 목적지 모델 | 본 기획서의 장기 확장 항목으로 미구현 |

시간 30% 단축, 예상 MAU, Retention 등의 기획상 목표는 실측 결과로 표시하지 않습니다.
